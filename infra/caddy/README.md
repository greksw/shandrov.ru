# Caddy configuration

Production web server configuration for `shandrov.ru`.

## Host

- Server: `web01.shandrov.ru`
- OS: Debian 13
- Caddy config: `/etc/caddy/Caddyfile`
- Document root: `/srv/www/shandrov.ru/current`

The website itself is deployed by GitHub Actions using versioned releases and an atomic `current` symlink.

## Configuration

`Caddyfile` in this directory is a tracked copy of the production configuration.

It provides:

- HTTPS with automatic certificate management
- HTTP to HTTPS redirects
- `www.shandrov.ru` to `shandrov.ru` redirect
- gzip and zstd compression
- custom `/404.html` handling
- security response headers
- Content Security Policy
- removal of the `Server` response header on HTTPS responses

The custom 404 handler contains its own security-header block because Caddy error handling does not inherit the normal response-header handler.

## CSP

Current policy intentionally allows:

- same-origin styles
- inline styles generated by Astro
- same-origin images and fonts
- `data:` images
- same-origin connections

JavaScript, frames, objects, workers and external connections are denied.

`connect-src 'self'` is required because Lighthouse loads `/robots.txt` using a same-origin network request. Using `connect-src 'none'` causes the Lighthouse SEO robots.txt audit to fail because of CSP.

## HSTS

Current probationary setting:

    Strict-Transport-Security "max-age=604800"

Do not add `includeSubDomains` or `preload` without first verifying HTTPS availability and requirements for every relevant subdomain.

After a stable operating period, `max-age` may be increased deliberately.

## Validate a candidate

On `web01.shandrov.ru`:

    sudo caddy validate --config /tmp/Caddyfile.candidate

Do not install a candidate that fails validation.

## Install

Create a backup first:

    sudo cp -a /etc/caddy/Caddyfile \
      /etc/caddy/Caddyfile.bak-$(date +%Y%m%d-%H%M%S)

Then install and validate:

    sudo install -o root -g root -m 0644 \
      /tmp/Caddyfile.candidate \
      /etc/caddy/Caddyfile

    sudo caddy validate --config /etc/caddy/Caddyfile

Reload only after successful validation:

    sudo systemctl reload caddy
    sudo systemctl is-active caddy

## Basic checks

    curl -sSI https://shandrov.ru/
    curl -sSI https://www.shandrov.ru/
    curl -sSI https://shandrov.ru/__404_test__/
    curl -sSI https://shandrov.ru/robots.txt

Expected statuses:

- `shandrov.ru/` -> 200
- `www.shandrov.ru/` -> 301
- unknown path -> 404
- `robots.txt` -> 200

Changes should be validated on a candidate configuration before being applied to production.
